# Support

JuDoctor is currently maintained through GitHub.

## Before opening an issue

Check:

1. [Known Issues](KNOWN_ISSUES.md)
2. [Installation](docs/INSTALLATION.md)
3. Existing GitHub Issues

## Bug reports

Use the bug report template and include:

- JuDoctor version
- Windows version
- CPU model
- GPU model
- installed RAM
- whether JuDoctor was started manually or with Windows
- expected behavior
- actual behavior
- reproducible steps

For monitoring/diagnosis issues, include the approximate time the problem occurred so the relevant local history can be inspected.

## Privacy when attaching evidence

Do not upload `mainpc.db`, logs, or screenshots before reviewing them yourself. Hardware/process metadata can still reveal machine-specific information even when JuDoctor does not collect file contents.

## Feature requests

Feature requests are welcome, but the `v1.0.x` line is stability-only. New features are evaluated only after repeated real-world evidence shows a common problem.

## Commercial / business interest

If you are interested in technician reports, multi-PC management, fleet visibility, or commercial use cases, open a feature request describing the workflow/problem rather than only naming a desired feature. This helps validate which paid direction is actually useful.
